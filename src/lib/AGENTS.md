- Contract PF/ESI lines are per-line formulas; optional keys `esiLimitOn` + `esiLimitBasis` ("payrate"|"earnings") decide ESI eligibility, `roundMode` ("up"|"nearest") rounds, and an uncapped EPF formula is never clipped — matches Pages Payroll settings without per-client code.
- Per-guard allowances live in `additions` (site-scoped `unit_id`, `repeat_monthly`/`end_date`, `prorate_by_days`, `counts_for_pf`/`counts_for_esi`); payroll and invoice apply them only via `applyEmployeeAdditions` (ESI-eligible additions also feed formula-based ESI lines, rounded once at the end) — person-specific pay never edits the shared contract rate.
- Professional Tax is one monthly slab per person via `ptForSite` (`pt-cross-site.ts`): a recorded Pages split (`pt_site_allocations`, per person/site/month) wins; otherwise each site charges slab(this site + already-processed sites) − PT already charged (`payroll_run_snapshots`) and Process re-checks — this is Pages' processing-order rule, so PT lands where Pages put it.
- PT and LWF use `units.pt_state` (work state, mirrors Pages' PT state) when set, else billing state/pincode — billing state is only the invoice address (often head office). LWF resolves pincode → state, falling back to the site billing state when the pincode is blank or outside every `pincode_ranges` row; Extra-Duty-only lines drop EPF/ESI but keep the contract PT row — matches Pages, and sites without a mapped pincode still get LWF.
- Invoices bill the saved `contract_resources` amounts, so any import or bulk write must store formula lines already evaluated exactly as the contract editor does on Save (`computeBenefitAmount`); otherwise pressing Save silently changes the billing rate.
- Formula variables that don't match a pay line on the role evaluate to 0 silently; `unknownFormulaVariables` (payroll-calc) lists them and the contract editor warns on Save. Any import or bulk formula write must check it — renamed items (`d_a`, `leave_with_wages`) and dropped items (`bonus_addition`) were the main cause of ESI/PF drifting from Pages.
- Attendance rules live only in the DB (`apply_guard_attendance_rules`, statement triggers `zz_attendance_rules_*` on attendance_entries): per guard per month the unit with most working days (tie = reached first, reliever-line ED days count too) is primary — its reliever lines are promoted to regular (whole-day ED → P) — and other units' Present days become ED; at the primary, Present beyond the payroll-days cap becomes ED. Conversions keep `rule_orig_code/ot` so re-runs are reversible; processed periods untouched; skip only via `SET LOCAL app.skip_attendance_rules='on'` on explicit user instruction — every source (UI, import, code) follows them. Any person can be entered at any unit (reliever lines accept P too, nothing is refused); the rules alone convert non-primary/reliever Present to ED.
- Explicit changes to attendance code, ED or cap provenance discard previous rule-original metadata in a before-update trigger; internal rule writes retain it, so recalculation never restores an obsolete mark over a correction.
- Monthly attendance rules persist non-primary `is_reliever` flags and synchronize recent editable site postings (`is_primary` plus `is_reliever`); primary-site cap ED stays regular — labels and payroll line classification must agree with the same database decision.

- Dashboard P&L mirrors payroll rules (period contract, attended roster, shift lines, unit PH); employer cost excludes billing markup — keeps margins aligned.
- Billing add-on refresh excludes reliever/management fee from CTC even when passed as extra employer lines — keeps CTC-only formulas consistent with the contract editor.
- Rate changes are versioned in `contract_rate_revisions`; payroll/invoice resolve per period via `applyRateRevisionsForPeriod` (day split), a daily job promotes due rates — past periods keep old rates.
- Period contract resolution (`fetchPeriodContract`) breaks equal start dates by status (active first) then newest `created_at` — overlapping contract copies otherwise made payroll/invoice flip between runs.

- Extra Duty rule (basis, multiplier, formula, ticked components) always comes from the contract resource via `withContractEdRule` (src/lib/ed-rule.ts), even when an employee has their own salary setup; all-unticked = ₹0 ED — so the contract choice is never silently replaced.
- Pages data: archived payslips are read-only `pages_payslip_archive` (never recalculated).
- Site-grain MIS exports group by unit, designation, billing rate — keeps contract lines separate.
- Punch/location listeners refetch at most every 30s (never per-row streams).
- Portal persistence is an explicit reference-list allowlist in session storage, owned by the root's real auth identity; never persist employee PII, permissions, financial results or signed links. Bounded freshness handles changes missed while closed.
- Contract pay lines with `contractOverride: true` (set when edited on the contract: amount, %, or formula) are contract-owned — editor overlays, `hydrateFormulasFromMaster` and statutory ESI must not overwrite them; Reset clears the flag.
- Invoice duty-rate exceptions use `invoice-duty-rates`; detail, print and exports price regular/ED quantities separately so totals reconcile without modifying payroll.
- Site-specific invoice ED bases resolve from unit code and contract designation in `invoice-duty-rates`, fed the saved monthly billing including benefits; invoice registers and finance summaries share this rule to avoid diverging totals.
- ESI on Extra Duty is opt-in per contract role (`contract_resources.ot_esi`: formulas copied from Cost Component Manager ESI lines); computeWages adds separate `edEsi` lines evaluated on each pay item's ED share, which statutory ESI placement skips — ED otherwise never carries PF/ESI/PT.
- EmployeePicker uses employee-picker-search filters; numeric searches check employee_code and mobile together so employee IDs are never mistaken for phone-only queries.
- Deployment directory reads are fully paged and session-gated; their employees-lite cache key has a deployment-specific suffix to prevent payroll pickers' smaller row shapes from hiding mapped guards.
