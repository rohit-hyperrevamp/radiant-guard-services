- Employees page loads working staff on open and inactive history only for the Inactive tab or offboarding filter, never active-tab search; reads use bounded batches and inline pickers render only searched options while open to prevent directory-wide interaction stalls.
- Successful employee saves patch the actual working/inactive query slices and refresh in the background; never hold the save dialog open waiting for full directory reads or insert incomplete new profiles into cache.
- Per-employee PH opt-out lives in `units.ph_excluded_candidate_ids` (whole employee) and `units.ph_excluded_days` ("candidateId|date"); attendance, payroll and invoice all skip unit PH credit for those employees — keep the three in step.
- Dashboard payroll/invoice/profit loads automatically but deferred: only after headline tiles paint and the section nears the screen; the last result per user+month+window paints from a capped localStorage snapshot while fresh figures refresh in the background — never block it behind a Generate step.
- Attendance quick-create (ID, name, start/end date) goes only through `quick_create_attendance_employee`; existing people (incl. inactive) are found via `quick_lookup_attendance_employee` and revived via `quick_reactivate_attendance_employee` — all Super-Admin-checked server-side, never direct candidate writes from the sheet, so duplicates are surfaced instead of re-created.
- Super Admin can pin a guard's regular site per month via `set_attendance_primary_unit` (table `attendance_primary_pins`); `apply_guard_attendance_rules` honours the pin over "most worked days" — never pin by editing attendance rows directly, or the next recalculation reverts it.
- Clicking an employee name on the attendance sheet shows per-site counts for the month via `attendance_employee_site_summary` (security-definer, counts only, caller must reach the viewed unit) — never query other units' attendance rows from the sheet, RLS hides them from scoped users.
